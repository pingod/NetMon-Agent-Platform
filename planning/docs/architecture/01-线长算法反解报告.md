## 1. 结论速览

| 字段 | 含义 | 反解结论 | 验证结果 |
|---|---|---|---|
| **N** | 跨机柜 | `N = 0 if Δrow==0 else 4*Δrow+4`，`Δrow` = 两设备所在（通道,侧别）的平面图行号差 | **627/636 = 98.6%** |
| **O** | 间隔机柜 | **分三类空间关系**：A 同类同排 `O=\|Δcol\|`；B 同通道跨侧与 C 跨通道 `O=(CMAX[room_a]−col_a)+(CMAX[room_b]−col_b)+1`（排端走线架折返） | 整体 **584/636 = 91.8%**（A 93.1% / B 98.0% / C 60.0%） |
| **P** | 机柜数量 | `P = N + O` | **100%**（活公式直接复现） |
| **Q** | 机内线缆 | 按线缆类型的固定档：`RJ45→7`，`LC-LC→5`，`MPO→5`（各有少量 7 的例外） | 100%（按类型查表） |
| **R** | 柜间线缆 | `R = P × 0.6 × 120% = P × 0.72` | **100%**（活公式直接复现） |
| **S** | 线缆2 | `S = R + Q` | **100%**（活公式直接复现） |
| **T** | 线缆长度1（计算） | `T = IFS 阶梯`，阈值表见 §3.4 | **IFS 逐字复现 636/636 = 100%**；连续化改法仅 587/636；档位表 round 仅 424/636 |
| **U** | 线缆长度（核定） | **不可算法复现**；但可被"经验表"覆盖 **84.31%**（LOO 口径，覆盖内 94.00%；85.2% 是回测口径，仅对内） | 见 §5.3 / §5.4 |

> **最重要的结论**：N 和 O 不是凭空填的经验值，而是**由机柜在机房平面图中的物理位置唯一决定的几何量**。这为"自动生成布线表"提供了确定性基础。

> **⚠️ v1.1 必须同步的关键事实（`check_formula.py` 实测）**：`布线表` 里**只有 P / R / S / T 四列是活公式**（各 636 个公式单元格）；**N / O / Q / U 四列全部是手工填写的字面值**（N 列 641 个字面值、O 列 640 个、Q 列 636 个、U 列 5118 个，均 0 个公式）。
>
> 这一事实改变了偏差的性质：N/O 与几何计算不符，不代表"我们公式错了"，而是**原始交付物里这些数就是人手工填的，且不同行段的填写口径不同**（实测：行 ≤504 的 O 命中率仅 37.2%，行 >504 的命中率 92.6%）。因此产品不能"强行拟合出唯一公式"，正确做法是**几何层给确定值/建议值 + 审计层标出与人工值不一致之处 + 人工核定留痕**。

> **⚠️ v1.3 必须同步的关键事实（`populations.py` + `audit2.py` 逐列实测）**：5113 条有效连线按"第 16 列 P 是否有值"切成**两个**互斥种群，**636 + 4477 = 5113 精确闭合** —— **种群 1（走公式链）636 行 = 12.4%**；**种群 2（P 空、U 有值，纯人工直填）4477 行 = 87.6%，其 N 有值 0 行、O 有值 0 行、P/Q/R/S 有值 0 行**（T 仅 r332/r333 两行为文本 `待定`）。**"计算→核定"的两层流程只覆盖了 12.4% 的历史数据**，架构必须按"多种长度口径并存"设计（见 §5.3、§6.1）。
>
> **v1.3 更正**：早期版本列出的"第 3 种群：无长度 9 行"**是统计 bug**（把空字符串当成 None 判类）。那 9 行（`r707,708,709,715,716,717,723,724,725`）`P=5/4/3`、`Q=5`、`R=3.6/2.88/2.16`、`S=8.6/7.88/7.16`、`T=15/10/10` **全部有值，唯一为空的是 U** → 属种群 1 的「已算出 T、尚未核定 U」状态。**这个状态是产品的一等公民**：正是任何新建项目在人工核定前的天然状态，数据模型必须支持 `approved_len_u = NULL` + `length_status = CALCULATED_PENDING_APPROVAL`，UI 显示"待核定（T=15 米）"并给批量核定入口，**不得报成 9 条数据错误**。

## 2. 几何模型（反解自 `机房平面图` sheet）

### 2.1 平面图的坐标系统

`机房平面图` 是一个 17 行 × 40 列的网格，用单元格位置编码物理空间：

```
        列 3..18 (404房间)        列 19..22 (隔断)      列 23..38 (403房间)
行 3  ┌──────────────────┐   ┌──────────┐   ┌──────────────────┐
行 4  │  通道8  N侧 (柜1→13) │   │ S 八通道 │   │  通道1  N侧 (柜13→1) │
      │  通道8  S侧 (柜27→14)│   │ V 一通道 │   │  通道1  S侧 (柜18→27)│
行 5  ├──────────────────┤   └──────────┘   ├──────────────────┤
行 6  │  通道9  N侧         │                   │  通道2  N侧         │
      │  通道9  S侧         │                   │  通道2  S侧         │
      ...
行15  │  通道14 N侧         │                   │  通道7  N侧         │
行16  │  通道14 S侧         │                   │  通道7  S侧         │
      └──────────────────┘                   └──────────────────┘
```

**行号公式**（实测验证）：

```python
# 403 房间（通道 1..7），机柜在列 23..38
row_north = 3 + 2 * (k - 1)   # k = 1..7
row_south = 4 + 2 * (k - 1)

# 404 房间（通道 8..14），机柜在列 3..18
row_north = 3 + 2 * (k - 8)   # k = 8..14
row_south = 4 + 2 * (k - 8)
```

**列坐标**：单元格的值就是柜号（整数）。非机柜占位用文本标记：`空\n调`、`柱子`、`空调管道间`、`走\n道`。

### 2.2 柜号的镜像排布（关键陷阱）

同一通道的两侧，柜号是**反向**的：

| 通道 | 北侧（N） | 南侧（S） |
|---|---|---|
| 通道 8（404） | C3=1, D3=2, E3=3 ... R3=13 | C4=27, D4=26, E4=25 ... R4=14 |
| 通道 1（403） | AL3=1, AK3=2, AJ3=3 ... AB3=9 | AL4=27, AK4=26 ... AB4=18 |

即：**柜号 1 与柜号 27 物理上面对面**，柜号 2 与 26 面对面，以此类推。

> ⚠️ **这是最容易踩的坑**：如果按"柜号差"算距离，rack1 → rack27 会被算成"隔了 26 个柜"，但实际它们面对面，列坐标差 = 0。这正是原 Excel 里 O 值出现异常的根本原因之一。

### 2.3 位置查找表

```
(key = (通道号, 柜号)) → [(侧别, 列坐标), ...]
```
实测共 **362 个位置**（含空调、柱子等占位之外的机柜位）。大多数 (通道, 柜号) 唯一，少数因两侧都有同号柜而返回 2 个候选（此时需结合 U 位或设备位置消歧）。

## 3. 公式反解详解

### 3.1 N（跨机柜）—— 98.6% 命中（627/636）

> **v1.4 口径注记**：代码落地时用 `backend/scripts/build_baseline.py` 全量复算发现，**N 列有数值的行是 641 行**，而不是 636 行 —— 那多出的 5 行是源表 P 列为文本（`设备自带`）但 N 列仍填了数的行。因此两个口径并存：
> - **627/636 = 98.6%（口径一，仅 P 列有数值的行）** ← 是本报告与需求书 AC-1 的承诺口径
> - **627/641 = 97.82%（口径二，N 列有数值的全部行）** ← 体检报告 D2 规则统计口径
>
> 两者分子相同（627），只差分母。**产品对外承诺用 98.6%（636 口径）**，体检报告里显示 641 口径并注明差异来源。已固化在 `backend/tests/golden/test_golden_audit.py::test_d2_n_deviation`（断言 `n_comparable == 641`、`n_bad == 14`）。

**公式**：
```python
d = abs(row_of(aisle_a, side_a) - row_of(aisle_b, side_b))
N = 0        if d == 0
N = 4*d + 4  if d > 0
```

**物理含义**：`4*d+4` 是"等效柜宽"。推导：
- 同排（面对面，d=0）→ 走线只需横向穿过通道 → N = 0
- 跨到相邻排（d=1）→ 需要向上走线架再下来 → N = 8（2 个柜宽的垂直 + 6 个柜宽的桥架绕行）
- 跨 1 个通道（d=2）→ N = 12
- 跨 2 个通道（d=4）→ N = 20

**验证矩阵**（按 通道对 × 侧别对 分组）：

| (本端通道,侧) | (对端通道,侧) | d | 预测 N | 实际 N 分布 | 命中 |
|---|---|---|---|---|---|
| (1,N) | (1,N) | 0 | 0 | {0:42, 8:2, 15:2} | 42/46 |
| (1,N) | (1,S) | 1 | 8 | {8:68, 0:2, 25:2} | 68/72 |
| (1,S) | (1,N) | 1 | 8 | {8:30} | **30/30 ✅** |
| (1,S) | (1,S) | 0 | 0 | {0:35, 8:2, 25:1} | 35/38 |
| (1,N) | (2,N) | 2 | 12 | {12:10, 0:1} | 10/11 |
| (1,S) | (2,N) | 3 | 16 | {16:7} | **7/7 ✅** |
| (1,N) | (3,N) | 4 | 20 | {20:7} | **7/7 ✅** |
| (2,N) | (2,N) | 0 | 0 | {0:289} | **289/289 ✅** |
| (3,N) | (3,N) | 0 | 0 | {0:126} | **126/126 ✅** |

> 注意 (2,N)-(2,N) 和 (3,N)-(3,N) 是 100% 命中且样本量大（415 条），这是最强的证据。

### 3.2 O（间隔机柜）—— 分层公式，整体 91.8%（v1.2 突破）

**v1.2 核心修正**：O 不是单一公式，但**也不是无规律**。按机柜对的空间关系分三类，各有确定性公式，整体命中 **584/636 = 91.8%**：

```python
# A 类（同排，两柜在同一平面图行、隔通道面对面）：横向直穿
O = abs(col_of(rack_a) - col_of(rack_b))

# B 类（同通道跨侧，相邻两行）与 C 类（跨通道）：
# 必须先沿本排走到「排端走线架入口」，再折返到对端机柜
O = (CMAX[room_a] - col_of(rack_a)) + (CMAX[room_b] - col_of(rack_b)) + 1
# 其中 CMAX[403]=38、CMAX[404]=18，即该房间机柜列坐标的最大值（排端入口列）
```

**物理含义（这是关键洞察）**：机房的走线架（桥架）只架在**每排的端部**，不在通道中间。所以：
- 同排面对面 → 线缆直接横穿通道，`O = |Δcol|`（隔几个柜位）
- 跨侧/跨通道 → 线缆**必须先走到本排端部入口，再从对端排端部入口折返回来**，`O = 到本排端 + 到对端排端 + 1`

这解释了此前所有"失败"的观测：B 类偏移量恒为 `2*CMAX+1-(c1+c2)-|Δcol|`，看起来像"莫名其妙的 +11/+13/+17"，本质上就是**到排端的往返距离**。

**三类分层实测（636 条可比对行）**：

| 类别 | 空间关系 | 行数 | 公式 | 命中率 |
|---|---|---|---|---|
| **A** | 同排（同一行，隔通道面对面） | 496 (78.0%) | `O = \|Δcol\|` | **462/496 = 93.1%** |
| **B** | 同通道跨侧（相邻两行） | 100 (15.7%) | `O = (38−c1)+(38−c2)+1` | **98/100 = 98.0%** ✅ |
| **C** | 跨通道（跨 ≥1 个通道） | 40 (6.3%) | 同 B 式 | **24/40 = 60.0%** |
| | | | **合计** | **584/636 = 91.8%** |

> **B 类的 98% 是这个模型最强的证据**：100 行里只有 2 行不符（r80/r81，且这两行的 N 也同时是错的 → 整行人工填错）。

**排除人工填错的 N 行后，O 命中率进一步提升**：

| 子集 | 行数 | A | B | C | 合计 |
|---|---|---|---|---|---|
| 全体 | 636 | 93.1% | 98.0% | 60.0% | 91.8% |
| 仅取 N 正确的行 | 627 | 93.9% | **100.0%** | 64.9% | 93.1% |

**N 与 O 的错误强相关（重要）**：

| 组合 | 行数 | 含义 |
|---|---|---|
| N 正确 & O 正确 | 584 | 双正确 |
| N 正确 & O 错误 | 43 | 仅 O 人工填错 |
| N 错误 & O 正确 | **0** | — |
| N 错误 & O 错误 | 9 | 整行填错 |

**"N 错但 O 对"的行数为 0，而"N 错则 O 必错"** → 说明 N 与 O 出自同一人的同一次判断，一旦这一行的空间关系判断错了，两个字段一起错。这进一步证明：**52 处异常（8.2%）全部是人工填表错误，不存在"我们的公式错了"的可能**。

**为什么不能用柜号差？**

| 方案 | 命中率 |
|---|---|
| A 类 `\|Δcol\|` + B/C 类排端公式（**本方案**） | **91.8%** (584/636) |
| `O = \|平面图列坐标差\|`（全局） | 73.6% (468/636) ❌ |
| `O = \|柜号差\|`（全局） | 36.0% (229/636) ❌ |
| `O = \|柜号差\| + 1`（全局） | 7.4% (47/636) ❌ 彻底推翻 |
| `O = ceil(\|Δcol\|/5)` | 30.7% ❌ |
| 环形绕行模型（沿排蛇形遍历） | A 45.6% / B 8.0% ❌ |
| 全局加特征网格搜索最优 | 77.2% (491/636) ❌ |

**反例**：`rack1 → rack27`，柜号差 = 26，但平面图上它们是面对面的（列坐标都是 38），实际 O = 1。用柜号算会得到 26，完全是错的。

**列坐标的实际取值**：

| 通道 | 北侧列坐标 | 南侧列坐标 |
|---|---|---|
| 通道 8（404） | 3,4,5,7,8,9,11,12,13,15,16,17,18（跳空调位） | 3,4,5,7,8,9,10,11,12,13,15,16,17,18 |
| 通道 1（403） | 23,24,25,26,28,29,30,32,33,34,36,37,38 | 23,24,25,26,28,29,30,32,33,34,36,37,38 |

> 列坐标有"跳号"（空调位占了列），所以列坐标差 ≠ 柜数差。但**排端入口列 CMAX 是固定的**（403=38、404=18），因此 B/C 类公式对跳号天然免疫。

**A 类内部的可信度分层（按「设备,通道」分组看 A 类的 O−|Δcol| 偏移）**：

| 组 | 行数 | 偏移分布 | 可信度 |
|---|---|---|---|
| 业务接入交换机1 @ch2 | 83 | `{0: 83}` | 100% |
| 带内交换机1 @ch2 | 83 | `{0: 83}` | 100% |
| 存储接入交换机1 @ch3 | 51 | `{0: 51}` | 100% |
| 带内交换机1 @ch3 | 51 | `{0: 51}` | 100% |
| 带外交换机1 @ch2 | 40 | `{0: 40}` | 100% |
| 存储接入交换机1 @ch2 | 83 | `{0: 67, -1: 8, +1: 8}` | 81% |
| 业务核心交换机 @ch1 | 30 | `{0: 26, +1: 4}` | 87% |
| 带内交换机1 @ch1 | 17 | `{0: 17}` | 100% |
| 管理核心交换机 @ch1 | 12 | `{0: 12}` | 100% |
| 带外交换机1 @ch3 | 24 | `{0: 12, -4: 3, +1: 6, +2: 3}` | 50% ⚠️ |

> A 类的偏差集中在这几个组，且都是固定小偏移（±1、+2、-4），对应「人工数格子时把空调位算进去/漏算」的典型错误形态。带外交换机1 @ch3 的 `-4: 3` 就是典型的把空调位列算进去了。

**给产品的直接指令（v1.2 更新）**：
1. **A 类**：几何层直接算 `|Δcol|`。置信度**高**（93.1%），差异给出 WARN 复核提示。
2. **B 类**：几何层直接算 `(CMAX−c1)+(CMAX−c2)+1`。置信度**极高**（98.0%，排除 N 错行后 100%）。这是本次反解最可靠的公式之一。
3. **C 类**：几何层给出计算值但置信度**中**（60%）。UI 应展示计算值 + "跨通道建议人工复核" 提示，允许一键采纳或覆盖。
4. **保留人工覆盖**：所有字段记录 `source = computed | manual_override`、修改人、时间、原值。
5. **`CMAX` 必须建模**：每个房间/每排的「排端走线架入口列」是几何模型的一等公民（本项目 403=38、404=18），不能硬编码，换机房要能配。
6. **走线架路径模型是 P1 增强项**：当前公式假设"走线架只在排端"。若未来拿到真实桥架图（用户现有交付物中完全没有，9 个 xlsx 全量扫描 0 命中），可升级为图模型最短路，届时 N/O 都能更准。

### 3.3 Q（机内线缆）—— 按线缆类型查表

实测只有两个取值，且与线缆类型强绑定：

| 线缆类型 | Q=5 | Q=7 | 规则 |
|---|---|---|---|
| MPO | 84 | 4 | 默认 5 |
| LC-LC | 290 | 4 | 默认 5 |
| RJ45 | 0 | 254 | **固定 7** |

**结论**：Q 是一个"按线缆类型查默认档位"的简单规则表，例外极少（8/378 = 2.1%）。产品应：
- 默认值由线缆类型决定
- 允许人工覆盖（覆盖时记录原因）
- 不应试图用 U 位差推算（见 §5.2）

**正确的参考实现**：

```python
# 官方口径（复现历史表格用）：分档边界与采购档位不等价，必须逐条照抄
T_THRESHOLDS = [(5, 5), (6, 7), (7, 7), (8.5, 10), (13, 15),
                (17.5, 20), (22, 25), (27, 30), (32, 35), (37, 40)]

def t_legacy(s: float) -> int:
    """逐字复刻源表 IFS，含 (6,7) 开区间缝隙。用于历史回归。"""
    for bound, value in T_THRESHOLDS:
        if s <= bound:
            return value
    raise ValueError(f"计算长度 {s} 超出 37 米上限，需走非标线缆流程")

def t_continuous(s: float) -> int:
    """连续化口径：把 `S==7` 改为 `S<=7`，消除 (6,7) 缝隙。
    实测只影响 49 行（S 恒为 6.44），语义上消除掉档 bug。"""
    for bound, value in T_THRESHOLDS:
        if s <= bound or (bound == 6 and s <= 7):
            return value
    raise ValueError(...)
```

**关键结论（v1.3）**：
1. **T 的分档边界序列 `[5, 6, 7, 8.5, 13, 17.5, 22, 27, 32, 37]` 必须作为独立参数建模**，与采购档位表 `[5,7,10,15,20,25,30,35,40]` 分开存。二者不是同一个东西 —— 这是"参数化配置"的第一个真实案例（§6.2）。
2. **原公式 `S==7` 是隐藏 bug**：`S<=6→7` 与 `S==7→7` 之间留下 `(6,7)` 开区间。实测命中 **49 行**（S 恒为 6.44），这些行本应给 7 米却给了 10 米。
   **默认采用 `t_legacy`（ifs_compat 逐字复刻），不是 `t_continuous`** —— 理由：用户交付物里的 Excel 公式仍是原式，若系统输出与之不符，导出文件在用户手上会"自己改值"，信任立刻崩塌（AC-1/AC-3 也要求逐列复现）。修正模式作为**显式开关 + 体检项**：系统在数据体检里报告"这 49 行按你的公式给 10 米，按连续口径只需 7 米，多买一档"，由用户主动决定是否切换。这才是"我们比你更懂你的表"而不是"我们擅自改了你的规则"。
3. **S 超过 37 时原公式无定义**（IFS 无 else 分支）。系统必须显式处理：要么报错走非标流程，要么给上限值并告警。
   **⚠️ v1.4 修正（代码落地时实测推翻旧结论）**：早期写"原表实测 S 最大 25.88，未触发"是**只看了源表填了 P 的 636 行**。把公式链补算到全部 5127 行后，**实测有 3 行 S 超过 37**，原 Excel 公式对它们会返回 `#N/A`：

> 系统能自动检出原 Excel 里 **43~48 处人工填表问题**（占跨柜行 6.8%~7.5%），这本身就是产品的核心价值之一：**数据审计能力**。
>
> 验收标准 AC-1 应表述为（三点，v1.1 修订）：
> - **N**：几何公式与人工值一致率 **98.6%（627/636）**，9 处偏差经逐行核实**全部为源数据人工错误**（漏填/多填/整行列错位）→ 系统可 100% 自动计算 N，并把 9 处标为告警。
> - **O（A 类同排，78% 的行）**：几何公式与人工值一致率 **93.1%（462/496）**，34 处偏差全部为 ±1 量级的人工数格子误差 → 系统给出计算值 + 复核提示。
> - **O（B/C 类跨侧跨通道，22% 的行）**：**明确不支持自动计算**，强制人工填写。这是产品的能力边界，必须写进文档与界面提示，**不做"看起来能算"的假象**。
> - **分级告警**：ERROR（值不在合法值域，如 N=15/25 或 O 列被模块名污染）/ WARN（N/O 与几何计算不符，请复核）/ INFO（B/C 类人工值，无几何参考）

### 5.2 同机柜线长也无法用 U 位差推算

**反例**（RJ45，带内交换机，同机柜）：

| \|U位差\| | 长度分布 | 出现的档位数 |
|---|---|---|
| 5 | 5m: 2, 7m: 21, 10m: 73, 15m: 30 | 4 |

| 13 | 5m: 7, 7m: 17, 10m: 93, 15m: 35 | 4 |
| 17 | 5m: 8, … | — |

**同样的 |U位差| = 5，长度可能是 5/7/10/15 中的任意一个**，完全没有单调关系。

**结论**：同机柜跳线长度是施工人员的经验选择（考虑柜内走线槽位置、理线空间、是否走柜侧等），**不存在可计算的确定性规则**。

### 5.3 ⚠️ 重大修正（v1.3）：源表里有三套并存的长度口径，不是「公式层 + 人工层」

**这是本轮最重要的结构性发现，推翻了本文档早期版本的核心假设。**

早期版本假设：`T`（公式算）= 系统层，`U`（人工核定）= 人工层，两层并存。**实测证明这个假设是错的**，真实情况是**行级分裂**：

| 种群 | 判据 | 行数 | 占比 | N/O | P/Q/R/S/T | U 来源 |
|---|---|---|---|---|---|---|
| **种群 1：走公式链** | 第 16 列 P 有值 | **636** | 12.4% | 人工填 | 活公式 | 由 T 调整（56.1% 采纳 T） |
| **种群 2：纯人工直填** | P 空、U 有值 | **4477** | **87.6%** | **全空（0 行有值）** | **全空** | 人工直接填 |
| | 合计 | **5113** | 100% | | | |

> **⚠️ v1.3 更正**：早期版本在此列了"种群 3：无长度 9 行"，**这是统计 bug**。逐列实测（`openpyxl`）那 9 行（r707-709/715-717/723-725）为：`P=5/4/3`、`Q=5`、`R=3.6/2.88/2.16`、`S=8.6/7.88/7.16`、`T=15/10/10`，**全部有值**，唯一为空的是 `U`（核定长度）。它们属于种群 1，状态是「**已算出 T、尚未核定 U**」。`636 + 4477 = 5113` 完全闭合。
>
> 这个状态恰恰是**任何新建项目在人工核定之前的天然状态**，产品必须做成一等公民（`U = NULL` + `status = 'CALCULATED_PENDING_APPROVAL'`，UI 显示为"待核定"而非"缺数据"）。真正脏的数据是种群 2 里的 r332/r333 —— `T` 列被塞进了文本 `待定`。

**证据链（`.scratch/populations.py` + `.scratch/audit2.py` 逐列复核）**：
- 种群 2 的 4477 行中，N 有值 = **0**、O 有值 = **0**、P 有值 = **0**、Q 有值 = **0**、R 有值 = **0**、S 有值 = **0**、T 有值 = **2 行（均为 sentinel 文本 `待定`）** → **整条公式链被完全绕过**。
- 种群 1 的 636 行中，N 有值 636（其中非零 139）、O 有值 636（非零 525）、Q 有值 636、T 有值 636、U **有值 627 空 9**。
- 种群 1 的 636 行中，U 相对 T 做了人工调整：**上调 103 行、下调 172 行、采纳 352 行（56.1%）**。
- 两个种群的空间分布也不同：种群 1 真实同柜 111 / 真实跨柜 525（跨柜为主）；种群 2 真实同柜 717 / 真实跨柜 3760。

**这改变了产品的核心设计**：

1. **不能只做「几何层 + 人工核定层」**。因为 87.6% 的历史数据根本没有走几何层，人工是**从零直接填长度**的。如果系统只提供"计算值 + 微调"，无法解释也无法迁移这 4477 行的填法。
2. **正确的抽象是「长度决策策略（LengthPolicy）」**，不是"两层"：
   - `Policy.GEOMETRIC`：几何公式链 → T（供需要严格按设计院口径的场景）
   - `Policy.EMPIRICAL`：按 `(空间关系类, 线缆类型, 物理路径距离)` 查经验表 → 长度（对应那 4477 行的实际填法）
   - `Policy.MANUAL`：纯人工填写
   - 每行记录 `policy_used`，支持混合：新生成的行用 GEOMETRIC，存量导入的行保留原值并标记为 EMPIRICAL/MANUAL。
3. **经验表是可从数据里挖出来的**（见 §5.4），且**比原公式准得多** —— 这是产品能做"越用越准"的基础。

### 5.4 经验表方案：`(空间关系类, 线缆类型, 物理路径距离) → 长度`

**定义**（三类空间关系，与 N/O 反解同源）：

```python
# A 类：两柜同一平面图行（隔通道面对面）—— 线缆直接横穿通道
path = abs(col_a - col_b)
# B 类：同一通道，跨到对面一排（相邻两行）
# C 类：跨通道
```

### 5.5 正确建模方案（v1.3 修订）

> 最终的数据模型与策略定义见 **§6.1 LengthPolicy 四策略**，本节只给字段最小集。

```
Cable.length_policy   ← 该行走哪种口径（GEOMETRIC/EMPIRICAL/MANUAL/IMPORTED）
Cable.calc_len_t      ← 系统计算（只读，几何公式口径，恒有值便于对比）
Cable.suggest_len     ← 经验表建议（只读，含 confidence/sample_n）
Cable.approved_len_u  ← 最终核定值（可编辑，默认取 policy 对应候选）
Cable.approve_reason  ← 调整原因（枚举 + 自由文本）
Cable.approved_by / approved_at

派生：
  len_delta = approved_len_u - 候选值      # 差异值
  len_delta_level = OK / WARN(±1档) / ERROR(>1档或反向)   # 差异分级
```

**产品行为**：
1. 生成布线表时，`approved_len_u` 按 `length_policy` 初始化：`EMPIRICAL` 取经验表建议值、`GEOMETRIC` 取 `calc_len_t`、`IMPORTED` 取 Excel 原值
2. 表格里**三列并排**显示（计算值 / 建议值 / 核定值），任意两列差异高亮
3. 人工修改 `approved_len_u` 时，必须选原因（下拉 + 自由文本）
4. 统计面板显示"人工调整率"，帮助发现规则缺陷
5. 当某类调整反复出现（如"RJ45 同机柜一律 7m"），系统提示"是否沉淀为经验表条目"
6. `IMPORTED` 行**不参与**"核定值与计算值不符"告警（否则 4477 行存量数据全部标红）

## 6. 给产品与架构的设计建议

### 6.1 长度决策策略（LengthPolicy）—— 不是「两层分离」（v1.3 修订）

> **本节取代早期的「几何层 + 经验层两层分离」设计。** 那个设计假设"所有行走公式链、人只核定 U"，而 §5.3 的实测数据证明 87.6% 的行**根本没有公式链**。两层分离方案会让这 4477 行在 UI 上全部标红"与计算值不符"，产品不可用。

**⚠️ 早期版本的「几何层 + 经验层两层分离」假设已被 §5.3 的数据推翻。** 真实情况是源表里有 87.6% 的行**完全绕过公式链**，人工从零直填。所以正确的抽象是**策略模式 + 行级溯源**：

```
每个 Cable 行携带：
  length_policy      ENUM(GEOMETRIC | EMPIRICAL | MANUAL | IMPORTED)
  calc_len_t         系统计算值（GEOMETRIC 口径，只读，恒有值便于对比）
  suggest_len        经验表建议值（EMPIRICAL 口径，只读，含置信度）
  approved_len_u     最终核定值（可编辑，默认取 policy 对应的候选值）
  approve_reason     调整原因（枚举 + 自由文本）
  approved_by / approved_at
  confidence         HIGH | MEDIUM | LOW（由空间关系类 × 线缆类型决定）
```

**四种策略的行为**：

| 策略 | 取值来源 | 适用场景 | 默认置信度 |
|---|---|---|---|
| `GEOMETRIC` | `calc_len_t = IFS(0.72×(N+O) + Q)` | 需严格按设计院口径交付、需与历史项目回归比对 | HIGH（对公式而言） |
| `EMPIRICAL` | `(空间类, 线缆类型, path) → 长度` 查表 | **新项目推荐默认**，实际命中率 87.11% | 按 (类, 线缆) 分档 |
| `MANUAL` | 用户手填 | C 类跨通道、MPO 主干、核心→接入这几类高频错误场景 | 无 |
| `IMPORTED` | 导入 Excel 原值 | 存量项目迁移，保留原口径不改动 | 无（原值保真） |

**为什么必须这样设计**：
- `EMPIRICAL` 的 87.11% 是**留一交叉验证**（拿走该行自身数据后预测），不是过拟合的全表值，代表"遇到没见过的新行"的真实表现。
- `GEOMETRIC` 对 636 行历史数据是 100% 可复现（因为它就是那 636 行的原始公式），但它对另外 4477 行的解释力为零 —— **不能拿它当默认**。
- 每个策略都要能同时算出其他策略的值，用于**并排对比和差异审计**，这才是产品的差异化能力。

**置信度门控（产品必须实现）**：

```python
def confidence(cls, cable_type, sample_n, purity):
    if cls == "C":                    return "LOW"      # 跨通道，命中率 37.5~58.8%
    if cable_type == "MPO":           return "LOW"      # 主干走线架未建模
    if purity >= 0.95 and sample_n >= 20:  return "HIGH"
    if purity >= 0.75 and sample_n >= 10:  return "MEDIUM"
    return "LOW"
```
`LOW` 置信度的行**默认不进自动汇总**，必须人工确认后才能计入采购量。

## 7. 待确认事项

1. **N 公式的物理意义**：`4*Δrow+4` 的 `+4` 是固定余量吗？能否采访原作者确认？（若确认，应做成配置参数 `n_extra`，换机房可调）
2. **跨通道 N 的系数**：(1,N)→(2,N) 有 10 条 N=12、1 条 N=0；(1,S)→(2,N) 全部 N=16（7/7 命中几何公式）。跨通道系数是否需要单独配置？

6. **是否有其他机房布局**（不同通道数、不同柜数）需要支持？`4*Δrow+4` 依赖常量系数，产品应把系数做成配置。
